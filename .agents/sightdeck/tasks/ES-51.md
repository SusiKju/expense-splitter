# Personenbezogener Einladungslink statt geteiltem Raumcode

## Ziel
Mit dem Raumcode allein kann man aktuell jede beliebige Person auswählen. Stattdessen soll jede Person über ihren eigenen Einladungslink eindeutig zugeordnet werden.

## Scope
- Pro Person ein Token, das im Raum gespeichert wird
- Pro Person ein Einladungslink (Raumcode + Token) statt eines gemeinsamen Links
- Beim Beitritt über den Link wird die Identität automatisch gesetzt, eine freie Auswahl gibt es nicht mehr
- Die Firebase-Regeln sollen die Identitätszuordnung absichern

## Schritte
1. Tokens pro Person im Datenmodell ergänzen und anlegen
2. Links pro Person im Personen- oder Teilen-Bereich erzeugen und teilen
3. Beitritt über den Link: Token prüfen und die Identität setzen
4. Identitäts-Modal umbauen, sodass die freie Personenwahl entfällt
5. Firebase-Regeln für identities/tokens anpassen
6. Tests schreiben

## Offene Fragen
- Was passiert mit bestehenden Räumen und Geräten, die schon zugeordnet sind (Migration)?
- Wie läuft die Selbstregistrierung neuer Personen?
- Soll man einen Link neu erzeugen können, wenn er verloren geht oder weitergegeben wurde?
