# Identitätsauswahl beim Betreten des Raumes erzwingen

Beim Betreten eines Raumes wird der User aufgefordert, sich zu identifizieren, indem er sich einer bereits eingetragenen Person zuordnet.
Ohne diese Zuordnung bekommt er keine Freigabe für den Raum.
Ziel: Alle Eingaben lassen sich dem jeweiligen User zuordnen.
Offene Fragen: Wird die Zuordnung pro Gerät gespeichert? Kann sie später geändert werden? Was passiert, wenn die eigene Person noch nicht eingetragen ist? Soll die Freigabe auch serverseitig über die Firebase-Regeln durchgesetzt werden?

## Entscheidungen (2026-09-24)

- **Pro Gerät, synchron im Raum:** bestehendes `state.devices[deviceId] = personId` wiederverwendet (gleiche Zuordnung wie im Änderungsprotokoll).
- **Später änderbar:** ja, über „Dieses Gerät gehört" im Änderungsprotokoll. „— nicht zugeordnet —" wählen → Gate greift sofort wieder.
- **Eigene Person fehlt:** Namensfeld im Modal legt die Person an und ordnet sie direkt zu (gesperrt, wenn die Kasse geschlossen ist).
- **Firebase-Regeln:** bewusst nicht. Ohne Auth ist die Geräte-ID clientseitig frei wählbar, Regeln könnten nichts echt prüfen (`ponytail:`-Kommentar im Code).
- Gate nur mit aktivem Raum (`_roomCode`); ohne Sync kein Zwang.

## Umsetzung

- `urlaubskasse.html`: Modal `#modal-identity` (Namens-Buttons, Name eintragen, „Raum verlassen").
- `needsIdentity()` / `ensureIdentity()` / `setIdentity()` / `addSelfAsPerson()`; `ensureIdentity()` läuft am Ende von `render()`, nach `roomCreate()` und `roomLeave()`.
- `openModal` blockiert andere Modals, `closeAllModals` (ESC, Backdrop, Welcome-Join) lässt das Identitäts-Modal offen, solange die Zuordnung fehlt.

## Verifikation

Browser auf `127.0.0.1:8934` (eigener localStorage, Fake-Raum `ZZZZZ9`, keine Firebase-Writes): Modal nach dem Laden offen; ESC/Backdrop/Menü schließen es nicht; Auswahl schließt es; Zuordnung aufheben öffnet es wieder; Name eintragen legt die Person an und ordnet sie zu; „Raum verlassen" schließt es.
